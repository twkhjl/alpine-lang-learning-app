# 功能完成度矩陣

## 說明

這份矩陣不是產品規格承諾，而是根據目前專案實作狀態整理的工程視角盤點。  
目的有兩個：

- 幫助接手者快速知道哪些功能真的存在
- 避免把「看起來像有」誤判成「真的完整可用」

完成度使用以下分級：

- `已完成`
- `基本可用`
- `部分完成`
- `未完成`

## 目前最值得補完的能力

### 第一組：穩定性

- 文案與編碼治理
- 更完整的後台 E2E
- deploy 後 smoke test

### 第二組：後台成熟度

- 資產上傳 / 刪除
- 更完整的錯誤回饋
- 審計與操作紀錄

### 第三組：可維護性

- `main.js` 模組化
- 後台 controller 抽共用 helper
- contract 文件持續更新

## 如何使用這份矩陣

如果你接下來要排工作，建議不要只看「功能有沒有頁面」，而要看：

- 狀態是不是 `已完成`
- 是否有自動化測試保護
- 是否還依賴人工維運判斷

這能避免在規劃時高估目前專案成熟度。
