# 測試策略與本地開發流程

## `package.json` 可見腳本

目前腳本不多，但很聚焦：

```json
{
  "test": "node --test local-tests/*.test.js",
  "test:e2e": "node local-tests/e2e-runner.js",
  "test:admin": "node --test local-tests/admin-*.test.js"
}
```

這代表測試主要分三層：

- 一般 Node test
- admin 專屬 test
- Playwright E2E

## `admin-pages.test.js` 的角色

這類測試很值得保留，因為它補的是「靜態頁面契約」：

- 頁面有沒有載入正確 shell
- 必要結構是否存在
- 某些關鍵 CSS / HTML 行為是否被破壞

像近期遇到的 modal `hidden` 被 CSS 覆蓋問題，就很適合透過這類測試守住。

---

## Worker 測試

`admin-worker.test.js` 的存在表示：

- Worker 不是完全靠手動驗證
- 至少有針對 handler、payload、錯誤回應做測試

這很重要，因為 Worker 是後台寫入安全邊界，一旦壞掉，後台大多數操作都會跟著壞。

---

## E2E Runner 的做法

`local-tests/e2e-runner.js` 做法相當直接：

- 用 Node 建一個簡單 static server
- 預設跑在 `127.0.0.1:4173`
- 用 Playwright 開 headless Chromium
- 逐步驗證前台與部分後台流程
- 若失敗會截圖到 `local-tests/output`

這種方式的優點：

- 不依賴額外 dev server 框架
- 對靜態網站很實用
- 失敗時有 screenshot 可追

---

## 目前已涵蓋的 E2E 類型

從 `e2e-runner.js` 可以看出至少驗證了：

- admin login shell 是否正常載入
- 未登入時 admin dashboard 是否會被導回 login
- 前台 app 是否能正常載入
- 預設是否進 card view
- words / tags 是否成功載入
- card 與 list 是否採用降冪 id 順序

這些案例不是很多，但都打在核心主流程上。

## 本地開發方式

### 前台 / 後台靜態頁面

因為專案本質上是靜態 HTML + JS，最簡單的方式是用本地 HTTP server 開。

例如：

```bash
python -m http.server 3000
```

或使用 Live Server 開啟：

- `http://127.0.0.1:5500/index.html`
- `http://127.0.0.1:5500/admin-login.html`

要注意：

- 不要直接雙擊 HTML 用 `file://` 打開
- 因為 fetch、origin、CORS 與 auth 行為會不準

---

## 後台本地測試的特殊前提

後台本地頁面雖然在本機開，但：

- 會連遠端 Supabase
- 會連遠端 Worker

所以本地手動測試是否成功，取決於：

1. `supabase-config.js` 指到哪個 Supabase 專案
2. `adminAuthApiUrl` 指到哪個 Worker
3. Worker 的 `ADMIN_ALLOWED_ORIGIN` 是否允許你的本地 origin
4. 線上 Worker 是否已部署最新版本
5. 線上 migration 是否已套用

---

## 常見測試落差

這個專案目前最大的現實是：

- Node test 全綠
- 不代表本地手動或遠端整合一定全綠

原因很簡單：

- Node test 多半驗證模組邏輯
- 真正整合還牽涉：
  - 瀏覽器行為
  - CORS
  - 部署版本
  - Supabase 遠端資料狀態

因此實務上應維持三層驗證：

1. 單元 / 模組測試
2. 本地瀏覽器手動驗證
3. 遠端實際 API 驗證

---

## 推薦的本地驗證清單

### 前台

1. 首頁能載入
2. 卡片能切換
3. 清單能搜尋
4. 語言切換正常
5. 音檔按鈕行為正常

### 後台

1. 未登入開 protected page 會被導回 login
2. login 成功後可進 dashboard
3. words list 可搜尋 / 篩選 / 分頁
4. word edit 可載入、建立、修改
5. tags 可新增、修改、刪除未使用 tag
6. assets 可搜尋與顯示 stored path

### API / 部署

1. Worker `OPTIONS` preflight 正常
2. Worker 主要 `POST/PATCH/DELETE` endpoint 正常
3. migration 已同步

## 建議補強的測試方向

1. 為 login 與 tag CRUD 增加真正的 E2E

3. 為 CORS 與 Worker route contract 建立 smoke test
4. 為 seed / translation 品質建立資料健診腳本
